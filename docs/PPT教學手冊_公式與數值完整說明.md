### 什麼是 AUC？

AUC = Area Under the ROC Curve（ROC 曲線下面積）。

- **ROC 曲線**：橫軸是「誤報率（把正常判成惡劣的比率）」，縱軸是「命中率（把真正惡劣正確抓到的比率）」
- AUC = 0.5 代表模型跟隨機猜測一樣差；AUC = 1.0 代表完美預測
- **我們的 0.703** 代表：模型 70.3% 的時間能正確地把「惡劣海況日」排在「正常海況日」前面。比隨機好，但不完美——因為模擬資料的雜訊本來就有，這是合理的。

### 什麼是 MILP 差距 0%？

MILP（Mixed Integer Linear Programming，混合整數線性規劃）是我們的排班求解器。

- 我們同時用兩種方法計算最優班表：(1) MILP 數學求解器 (2) 貪婪法（一個一個派，不回頭）
- 差距 0% 代表：**在 8 艘船、12 人的規模下，貪婪法恰好已經達到全域最優**
- 這不是缺陷，是數學上的正確結果：問題規模小，搜尋空間有限，貪婪法不會遺漏最佳解

## Section 04：排班引擎（最核心的部分）

### 第 18 頁　四大核心功能

這頁解釋我們的系統能做哪些「純海象資料系統做不到的事」：

#### 1. 人員疲勞指數（公式）

```
疲勞分 = (連續值勤天數_標準化 × 60%) + (近7日累計工時_標準化 × 40%)
```

- 滿分 100 分
- 「連續值勤」佔 60%（重要性更高，因為不休息最傷身體）
- 「近 7 日累計工時」佔 40%（看最近一週的工作量）
- 分級：< 40 = 低疲勞（綠），40–65 = 中疲勞（橘），≥ 65 = 高疲勞（紅）

**本次最高疲勞**：黃峻，連續值勤 5 天、7日工時 45.7h，疲勞分 66（高），自動配置港口值守。

#### 2. 工時公平性 Gini 係數

**Gini 係數**借用自經濟學的「貧富差距衡量」：

- **0** = 完全平均（每個人工時完全一樣）
- **1** = 極度集中（所有工時都落在一個人身上）
- **本系統 Gini = 0.031** → 非常接近 0，代表 12 名人員的累積工時分配極均勻

**Lorenz 曲線**是 Gini 的視覺化：畫出「人員累積比例」vs「工時累積比例」。如果每個人工時完全一樣，這條線就是對角線（45度）。我們的曲線幾乎貼著對角線，所以 Gini 很低。

#### 3. 船艦可用性

**公式**：
```
可用度 = 1 - (距上次維護後的累計出航趟次 / 維護間隔 45 趟)
≤ 15% 代表「快需要維護了，不能再派出」
```

- MAINT_INTERVAL = 45（每 45 趟需維護）
- 如果某艘船已連續出航 38 趟（45 × 0.85 = 38.25），剩餘可用度只有 15%，自動標記「需維護」
- 本次：8 艘船全部可用（可用度都 > 15%）

### 第 22 頁　MILP 數學模型

**MILP 是什麼？**

Mixed Integer Linear Programming（混合整數線性規劃）：

- **Mixed Integer（混合整數）**：有些決策變數只能是 0 或 1（例如「這個人派去這艘船」=1，「不派」=0），不能是小數
- **Linear（線性）**：目標函數和所有限制條件都是線性的（沒有平方、沒有指數）
- **Programming（規劃）**：這裡不是「程式設計」，是「計畫、最佳化」的意思

**我們的排班問題轉化成 MILP 的方式**：

```
決策變數：
  x[i][j] = 1 表示「人員 i 被指派到船艦 j」，= 0 表示不指派

目標函數（最小化）：
  Σ cost[i][j] × x[i][j]
  cost = 疲勞分 × 0.5 + 外海暴露率 × 0.5（派越疲勞 / 暴露越高的人到外海，成本越高）

限制條件：
  1. 每個人最多只能被指派一艘船（不能一個人同時在兩艘船）
  2. 每艘船最多一組人員（一艘船不能兩個人）
  3. 各海域員額要達到 zone_slots 的最低要求
  4. 高疲勞（≥65）者只能配港口
```

**HiGHS 後端**：scipy.optimize.milp 呼叫的是 HiGHS 求解器，它是目前最快的開源線性規劃求解器之一，2021 年獲得運籌學領域的 Beale–Orchard-Hays Prize。

### 第 23 頁　最優性驗證

| 數字 | 意思 |
|------|------|
| **161.2** | MILP 求解的最低總指派成本 |
| **161.2** | 貪婪法算出的總指派成本 |
| **0.0%** | 兩者差距（= (161.2 - 161.2) / 161.2 × 100%） |

**為什麼兩個都是 161.2？**

因為在 8 艘船 × 12 人的規模下，搜尋空間不大，貪婪法（從疲勞最低的人開始依次指派）恰好就找到了全域最優解。MILP 只是確認「沒有更好的解存在」。

這不是「MILP 沒有用」——而是「MILP 提供了數學證明」。如果系統規模擴大（30 人、20 艘船），貪婪法就可能錯過更好的解，那時 MILP 就會有明顯差距。

### 第 27 頁　時序模擬模型（AR(1)）

**為什麼不直接隨機抽？**

如果每筆紀錄的海況都獨立隨機抽，那今天大浪、明天就可能突然平靜。但真實世界的天氣有「慣性」——颱風或鋒面持續 3–7 天，不會一天一個樣。

**AR(1) 模型**（一階自回歸）：

```
今日海況嚴重度 = α × 昨日海況嚴重度 + (1-α) × 隨機擾動
```

- α ≈ 0.6–0.8（「慣性係數」，前一天的影響佔 60–80%）
- 這讓生成的資料有「持續性結構」
- 正因為有這個時序結構，後續 Markov 模型和 RandomForest 才有可以學習的規律

**效果驗證**：RandomForest 的 AUC = 0.703 > 0.5，代表確實有時序訊號可以學，而不是純雜訊。

### 第 29 頁　資料清洗（三步驟）

```python
# 步驟 1：移除缺失值
df = df.dropna(subset=['check_in', 'check_out', 'duty_zone', 'sea_state', 'vessel_id'])

# 步驟 2：計算工時，保留合理範圍
df['hours'] = (df['check_out'] - df['check_in']).dt.total_seconds() / 3600
df = df[(df['hours'] >= 4) & (df['hours'] <= 14)]

# 步驟 3：生成月份標籤
df['month_str'] = df['work_date'].strftime('%Y-%m')
```

- 剔除率 < 1%（資料品質好，幾乎沒有異常）
- 合理工時範圍：4~14 小時（太短 = 沒打到卡，太長 = 資料錯誤）

| **F = 249.1** | ANOVA 的 F 統計量 | 海況對工時影響極顯著 |

| **R² = 0.801** | OLS 判定係數 | 模型解釋 80.1% 的工時變異 |
| **Gini = 0.031** | 基尼係數 | 工時分配近乎完全均等 |

### 第 32 頁　ANOVA（變異數分析）

**問題**：「不同海況下（平靜/輕浪/中浪/大浪），平均工時有沒有顯著差異？」

**ANOVA 的邏輯**：
- H₀（虛無假設）：四組平均工時都一樣（海況跟工時沒關係）
- H₁（對立假設）：至少有一組平均工時不一樣

**F 統計量公式**：

```
F = 組間變異 / 組內變異
  = (各組均值與總均值的差異) / (各組內部的隨機波動)
```

- F 越大，代表「各組之間的差異」比「各組自己內部的雜訊」大得多
- **F = 249.104**（非常大），**p < 0.0001**（遠小於 0.05 的顯著水準）
- 結論：拒絕 H₀，海況顯著影響工時

**具體差異**：大浪的工時中位數比平靜天低約 1.5 小時（因為大浪提前下勤 100 分鐘）。

**什麼是 p 值？**
p 值 = 「假設 H₀ 為真，觀察到這麼極端的結果的機率」。
p < 0.0001 代表：如果海況真的對工時沒影響，觀察到 F=249.1 這麼大的機率不到萬分之一。所以我們有把握 H₀ 是錯的，可以拒絕它。

### 第 33 頁　卡方獨立性檢定

**問題**：「海域（港口/近海/外海）和海況（四種）是不是互相獨立的？」

**卡方的邏輯**：
- H₀：海域和海況彼此獨立（知道在哪個海域，不能預測海況）
- H₁：它們有關聯（外海更容易大浪）

**卡方公式**：

```
χ² = Σ (觀察次數 - 期望次數)² / 期望次數

期望次數 = 該列總和 × 該欄總和 / 全部總和
```

- **df（自由度）= (列數-1) × (欄數-1) = (3-1) × (4-1) = 6**
- **χ² = 232.811**（非常大），**p < 0.0001**
- 結論：拒絕 H₀，海域與海況分布有顯著關聯（外海大浪比例 ≈ 20%，港口只有 ≈ 1%）

這個結果**直接支持排班引擎的邏輯**：外海風險高，所以惡劣海況時要減少外海員額。

### 第 34 頁　OLS 多元線性迴歸

**問題**：「工時主要受哪些因素影響？影響多大？」

**OLS（Ordinary Least Squares，普通最小二乘法）**：找一條線（這裡是多維超平面）讓預測誤差的平方和最小。

**模型**：

```
工時 = β₀ + β₁×海況等級 + β₂×海域距岸 + β₃×星期 + β₄×上工時刻 + ε

（標準化後的係數，可以直接比大小）
β₁（海況等級） = -0.530
β₂（海域距岸） ≈ -0.004（幾乎無影響）
β₃（星期）      = -0.018（很小）
β₄（上工時刻）  = -0.554（最大）
```

**R² = 0.801 是什麼意思？**

```
R² = 1 - (模型殘差的變異 / 原始工時的總變異)
```

R² = 0.801 代表：這個模型解釋了 80.1% 的工時變異。剩下 19.9% 是模型沒有考慮到的因素（或純隨機）。

**為什麼「上工時刻」的係數最大（-0.554）？**
- 早上 7 點開始值勤，能工作更長；9 點才開始，工作時間自然短
- 係數是負值，代表「上工越晚，工時越短」（方向一致）
- 「標準化」的意思是：把所有變數都轉換成「幾個標準差」的單位，這樣不同尺度的變數可以直接比係數的大小

**numpy.linalg.lstsq**：我們用 NumPy 直接算最小二乘解（不依賴 statsmodels），公式是：
```
β = (X'X)⁻¹ X'y
```

### 第 35 頁　Spearman 相關矩陣

**為什麼不用 Pearson 相關係數？**

Pearson 假設變數是連續且常態分布的。但「海況」（平靜/輕浪/中浪/大浪）是**有序離散變數**（ordinal），不是連續的數值，用 Pearson 不合適。

**Spearman 相關係數**：先把數值換成排名（第幾名），再計算排名之間的 Pearson 相關。這樣就不需要常態假設，適合有序變數。

**三個主要發現**：

| 變數對 | r 值 | 意思 |
|--------|------|------|
| 工時 ↔ 上工時刻 | -0.65 | 上工越晚，工時越短（強負相關） |
| 工時 ↔ 海況等級 | -0.56 | 海況越差，工時越短（強負相關） |
| 海況 ↔ 海域 | +0.43 | 外海海況確實比港口惡劣（中正相關） |

## Section 07：預測與機器學習

### 第 37 頁　時間序列預測（雙模型）

**線性外推（上圖）**：
- 把每週值勤量當成時間序列
- 畫一條最佳擬合直線（y = a + b×週數）
- 延伸到下一週，得到預測值 ≈ 48 筆
- 加上 95% 信賴區間帶（預測不確定性的範圍）

**Holt 雙指數平滑（下圖）**：

```
水準方程：L_t = α × y_t + (1-α) × (L_{t-1} + T_{t-1})
趨勢方程：T_t = β × (L_t - L_{t-1}) + (1-β) × T_{t-1}
預測：ŷ_{t+h} = L_t + h × T_t
```

- α = 0.8（對近期資料加更多權重的水準平滑參數）
- β = 0.5（趨勢追蹤的平滑參數）
- 這兩個參數是用**一步預測 SSE 網格搜尋**找到的最優值
  （網格搜尋 = 嘗試很多 α, β 的組合，找讓誤差最小的那個）
- Holt 預測 ≈ 40 筆（比線性外推少，因為給近期下降趨勢更多權重）

**為什麼用兩個模型？**
兩個模型都指向「大約 40~48 筆」，互相印證。如果兩個預測差很多，代表近期有趨勢轉折，需要特別注意。

**純 NumPy 自行實作**：我們沒有用 statsmodels 等套件，而是直接用 NumPy 實作 Holt 算法。這展示了對算法本身的理解。

### 第 38 頁　RandomForest 海況預測

**任務**：預測「明日是否為惡劣海況日（中浪以上比例 ≥ 35%）」

**為什麼 AUC = 0.703，但準確率（acc）只有 0.692？**

因為這是個不平衡的分類問題：
- 原始正例率（惡劣海況日）只有 4%，如果模型全部猜「不惡劣」，準確率可達 96%，但完全沒用
- 我們做了以下調整使問題更平衡：
  - 把「中浪以上比例 ≥ 35%」定義為正例（惡劣），讓正例率達到約 25%
  - class_weight = balanced（讓模型對少數類別給更高懲罰）
- 調整後 acc 0.692 比亂猜有意義得多，AUC 0.703 > 0.5 代表有實際預測能力

**GridSearchCV 超參數搜尋**：
找最佳的三個參數組合：
- `max_depth`（樹的最大深度）= 8
- `min_samples_leaf`（葉節點最少樣本數）= 1
- `n_estimators`（樹的數量）= 150

**TimeSeriesSplit(5) 為什麼重要？**

一般交叉驗證（k-fold）會把未來的資料混進訓練集，讓模型「看到未來」，評估結果虛高。

TimeSeriesSplit 保證：**訓練集永遠在測試集的時間之前**。
```
Fold 1: 訓練[1~100] 測試[101~120]
Fold 2: 訓練[1~120] 測試[121~140]
...（時間順序）
```

CV AUC = 0.618 ± 0.082（4 折交叉驗證的平均 ± 標準差）

### 第 39 頁　Markov 海況轉移

**Markov 鏈**：只用「現在的狀態」預測「下一個狀態」（不需要更早的歷史）。

**轉移矩陣的計算方式**：

```python
# 統計「今天是狀態 A，明天是狀態 B」出現了幾次
counts[A][B] += 1
# 把每一行除以行的總和（轉換成機率）
P[A][B] = counts[A][B] / sum(counts[A])
```

結果是一個 4×4 的矩陣，橫軸是「今日海況」，縱軸是「明日海況」，格子裡是轉移機率。

**預測未來 7 天**：

```python
# 從今日海況的機率分布開始
state = [今日各海況機率]
# 連乘轉移矩陣 7 次
for day in range(7):
    state = state @ P
# 7天後的「大浪機率」
rough_7day = state[大浪]
```

**本次結果**：7 天後大浪期望機率 = 13.6%。超過 15% 會自動觸發排班預警（本次未觸發）。

### 第 40 頁　Isolation Forest 異常偵測

**兩種方法的差異**：

| 方法 | 看的維度 | 抓到的異常 |
|------|---------|---------|
| Z-score | 只看工時單一維度 | 工時過長或過短 |
| Isolation Forest | 工時+海況+海域+打卡時刻+星期（5維） | 情境組合異常 |

**Isolation Forest 的原理**：

對每個資料點，隨機建很多「隔離樹」（Isolation Tree）。正常資料點難以被孤立（需要很多次分割），異常資料點容易被孤立（幾次分割就獨立了）。

```
異常分數 = 2^(-平均樹深度/c(n))
分數越接近 1 → 越可能是異常
```

**5% 污染率（contamination=0.05）**：我們設定「預期有 5% 的資料是異常的」，讓模型相應地調整閾值。

**互補效果的例子**：一個人在港口、平靜天、週一工作了 12 小時。工時本身在正常範圍，Z-score 抓不到。但 Isolation Forest 知道「港口+平靜+工時12h」的組合很少見，會標記為異常。

### 第 43 頁　工時公平性（Lorenz / Gini）

**Lorenz 曲線計算步驟**：

```python
# 1. 計算每個人的總工時
person_hours = [885, 901, 870, ...]  # 12 個人

# 2. 從小到大排序
sorted_hours = sorted(person_hours)

# 3. 計算累積比例
x = [0, 1/12, 2/12, ..., 1]    # 人員累積比例（x軸）
y = [0, cumsum[0]/total, ...]   # 工時累積比例（y軸）

# 4. Gini 係數 = 2 × (對角線面積 - Lorenz曲線下面積)
gini = 1 - 2 * np.trapz(y, x)
```

**本次 Gini = 0.031 的解讀**：

Lorenz 曲線的 x, y 座標：
```
(0.000, 0.000)  ← 起點
(0.083, 0.075)  ← 8.3% 的人擁有 7.5% 的工時
(0.167, 0.153)
...
(1.000, 1.000)  ← 終點
```

這條曲線幾乎等於對角線（完全平均），Gini 趨近於 0，說明排班系統歷史上做到了均勻分配工作量。

## 常見觀眾問題 QA

**Q：你的人員資料是真實的嗎？**
A：不是。為了保護個人隱私，人員資料是用 Python 腳本生成的模擬資料，共 12 名，模擬 2025-12-05 到 2026-06-06 共 6 個月的值勤紀錄。海象資料部分來自中央氣象署開放 API，無金鑰時自動用模擬資料取代。

**Q：AUC 0.703 算好嗎？**
A：在有噪音的模擬資料下，0.703 是合理的結果。AUC > 0.7 在實務上通常被認為是「可接受」的預測能力。更重要的是，我們使用 TimeSeriesSplit 避免了未來資料洩漏，確保評估的誠實性。

**Q：MILP 差距 0% 是不是代表 MILP 沒有必要？**
A：不是。MILP 提供的是「數學保證」——即使貪婪法這次恰好找到最優解，MILP 還是必要的，因為它能證明「這就是最優解，沒有更好的了」。而且當系統規模擴大（更多人員和船艦），貪婪法就可能錯過最優解，那時 MILP 的差異就會顯現。

**Q：海象資料從哪裡來？**
A：中央氣象署（CWA）有開放資料 API 提供浮標觀測，包含波高、水溫等。我們使用 fetch_sea_data.py 抓取，無 API 金鑰時以模擬資料取代。共 736 筆，涵蓋 4 個浮標站。

**Q：為什麼用 Markov 還要用 RandomForest，兩個都要嗎？**
A：兩個模型預測的東西不同：
- **RandomForest** 預測「明日」是否惡劣（輸入是今日特徵，輸出是明日標籤）
- **Markov** 預測「未來 7 天」惡劣機率（只用轉移機率矩陣連乘）
兩個互補：RF 短期準、Markov 長期看趨勢。

**Q：Gini 係數只有 0.031，這是因為模擬資料刻意設計的嗎？**
A：部分是。我們在生成資料時設計了輪班機制（每個人出勤機率相似），這自然會讓 Gini 偏低。但這也反映了「如果排班系統正常運作，工時應該是均勻的」這個目標——Gini 低正是系統正確運作的證明。

**Q：排班只有 7 人，其他 5 人呢？**
A：本次明日（2026-06-07）班表共排 7 人值勤，剩下 5 人是輪休或不當班狀態。系統的設計是「不強制全員每天都出勤」，而是根據當天海域需要的員額動態決定出勤人數。
